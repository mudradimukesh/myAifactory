---
name: factory-coordinate
description: Coordinate bounded factory tasks, cumulative verification, budgets, and recovery through runner operations.
---

Reconstruct the run from approved brief, task records, exact candidate, decisions, failure history, and retained evidence. Resolve contradictions before dispatch. Select bounded tasks with explicit inputs, expected artifacts, permitted writes, and observable completion criteria.

Request runner operations for role invocations, candidate capture, accepted checks, and independent review. Do not recursively dispatch agents from workers. Use separate fresh discovery or design invocations when performing those responsibilities. Keep one implementation writer and obey the runner's concurrency limit.

Track cumulative acceptance across slices, exact candidate identities, run-wide resource use, disclosure records, and recovery. Budgets include failed attempts, retries, and continuations. Never reset allowances on resume or silently replace unavailable models. Until a provider and finite budget are approved, keep live model calls disabled.

Route application and startup repairs to Developer. Require fresh verification for every replacement candidate. Worker completion and self-reported success cannot accept a candidate. A missing required check, unresolved blocking review, or unexplained flaky check blocks handoff.

Record routine decisions within delegated authority through runner operations. Ask the client about consequential unresolved product intent or added scope. Requests for release follow the named release owner's authority. Handoff readiness is not release.

Return a compact restart record with objective, current revision, accepted criteria, remaining failures, evidence paths, resource use, and the next bounded action. Preserve recoverable partial work and process ownership when interrupted.

Use the approved subscription-native Claude or Codex execution profile. Assign the strongest approved model to orchestration and a lower-cost approved model to a bounded worker task when its measured results meet the same acceptance criteria. Record the actual runtime and model; subscription access does not imply unlimited usage or authorize paid API fallback.

Give each worker a compact context contract containing its responsibility, objective, approved requirements, exact base or candidate, relevant artifact paths, writable scope, required output, resource allowance, and stopping condition. Link bulky source and logs instead of repeating them. Include relevant failed attempts so a fresh worker does not repeat a disproven approach. Workers request specialist help through Coordinator, never by spawning workers themselves.

When assessing factory changes, distinguish inspected code, executed evidence, and recommendations. Compare each proposed control with the existing design before adding it. Evaluate model or workflow changes against the same acceptance requirements, including known-correct and seeded-defect cases. Count failed attempts and human intervention; cheaper replies alone do not establish lower cost per accepted task.
