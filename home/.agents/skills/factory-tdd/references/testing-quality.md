# Testing quality

A meaningful assertion observes behavior required by acceptance through a public interface or a persisted external effect. Expected values come from the specification, independently reviewed annotations, or a separately derived calculation. Copying the implementation's output or algorithm into the oracle cannot establish correctness.

Use mocks at external boundaries when the behavior under test does not require the real dependency. A mocked service proves behavior under that response, not integration with the real service. Record environment and dependency limits. Startup failures, timeouts, skipped mandatory checks, and missing evidence are non-passing outcomes.

Coverage includes the changed journey, meaningful error cases, and cumulative accepted journeys. A replacement candidate invalidates prior candidate-specific evidence. Keep the first failing result when rerunning; unexplained flakiness remains unresolved.

Geometry evaluation requires independent annotations and explicit units, coordinate transforms, and tolerance. Report wall, opening, room, and furniture errors separately, including false positives and missed objects. Scene validity and nonblank rendering do not prove reconstruction accuracy. Unknown scale must not become an asserted measurement.

Preserve invalid input cases as rejection tests when required by the project profile. Report exclusion reasons and cohort sizes. Never remove a hard valid case or weaken an agreed threshold to improve a score. Training or repair examples cannot also be described as unexposed evaluation cases.

A useful test distinguishes the required behavior from a plausible defect. Check whether the assertion would still pass if the subject always returned an empty or undefined result. An empty result may be correct for rejection behavior, so pair it with a meaningful accepted case when needed. Configuration behavior should be exercised through the operation that consumes the setting; literal pins of prompt wording or implementation constants do not establish product behavior.
