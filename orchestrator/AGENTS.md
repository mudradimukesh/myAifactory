# Orchestrator kit maintenance

Read GUIDE.md before changing this harness. Keep it goal-neutral: current goals, credentials, transcripts and run artifacts belong outside the repository. Legacy p1/pilot filenames are compatibility names, not a product brief.

After each diagnosed incident or fix, update GUIDE.md with the symptom, cause, remedy, regression, evidence limits and measured cost when known. Preserve failed attempts and unknown usage. Do not claim the originating run completed; acceptance was still blocked when this kit was extracted.

An orchestrator that has delivered an actionable ruling goes idle until the lead alerts it. Verify notification delivery before relying on that behavior. Do not replace a broken alert channel with model polling loops. Fix routine diagnosed problems within delegated authority without repeatedly asking the user; mandatory platform approvals still apply.

Use one builder and one independent reviewer by default. Keep fixed commands in tools, not additional model calls. Reassess internal budgets using actual cumulative usage. New tasks target80% coverage unless their explicit contract requires otherwise; never lower a running task's gates retrospectively.
